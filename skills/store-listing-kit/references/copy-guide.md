# Copy guide

## Screenshot captions

- One idea per screenshot; the caption names the benefit, the screen proves it.
- 2 lines, ≤ ~22 characters per line. Line 1 sets up (regular weight), line 2 is the payoff
  (bold + marker underline). A subtitle of ≤ 50 characters adds the specific.
- Order: core action → main feature → insight/value → trust promise → differentiator.
- Concrete beats clever: "Log an expense / in 10 seconds" beats "Money made simple".
- The lifted card shows the exact element the caption talks about.
- Translate captions natively; don't keep English idioms. Check each line still fits.

Patterns that work: `<verb> <object> / in <time>`, `<feature> that / <benefit>`,
`See where / <thing> goes`, `No <friction>. / <promise>.`, `Made for / <audience>`.

## Short description (Play, 80) / subtitle (iOS, 30)

Lead with the core action and the strongest differentiator. No keyword stuffing, no emoji walls,
no "best" / "#1" / pricing claims.

## Full description

```
<one-line hook>

<2–3 sentence paragraph: what it is, the core action, the main friction it removes>

WHY <APP>
• <benefit: proof>   (3–5 bullets)

<FEATURE AREA>
• <capability>       (3–4 bullets per area, 2–4 areas)

<closing line: data/privacy statement + privacy policy URL>
```

Uppercase headings and `•` bullets render in both consoles (no Markdown support). Every bullet
needs ledger evidence. Remove platform-specific instructions from the other platform's copy.

## Release notes

First release: one or two sentences on what the app does. Later: user-visible changes only.

## Banned

Ratings, review quotes, download/user counts, awards, "#1", "best", competitor names, prices in
images, features not in this build, "free forever" unless decided, mentions of other platforms
("also on iPhone") in a Play listing.
