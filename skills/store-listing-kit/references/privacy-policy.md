# Privacy policy outline

Write it from the data inventory, not from a generic template. Every sentence must be true of
the build being shipped; update the policy before a build that changes data handling ships.
Publish it at a public HTTPS URL (no login), in every listing language (one page with language
sections is fine — stores take one URL).

Sections:

1. **Summary** — 2–3 sentences: what the app keeps, where, and the headline promises.
2. **Who we are** — publisher name as shown in the store, contact email.
3. **What stays on the device** — list each data type (records, media, settings).
4. **What we collect** — be exact. "Nothing" is valid only if there is no network call, analytics,
   crash reporting or ad SDK. Name each third party and what it receives otherwise.
5. **Permissions and why** — each runtime permission and the user action that triggers it.
   Biometrics: the OS verifies; the app only receives success/failure.
6. **Backups** — OS backup behaviour as configured (Android Auto Backup rules, iCloud backup),
   including what is *excluded*.
7. **Deleting your data** — in-app deletion, clearing storage, uninstalling, account deletion (if
   accounts exist: in-app and web paths are required by both stores).
8. **Security** — what protections exist (app lock, OS sandbox). Never claim encryption you
   haven't verified (e.g. "end-to-end").
9. **Children** — audience statement matching the store's target-audience answer.
10. **This website** — cookies, analytics, server logs, forms.
11. **Changes** — how changes are announced; effective date at the top.
12. **Contact**.

Keep the store's data-safety / App Privacy answers consistent with this text.
